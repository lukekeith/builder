# Claude-first Codex Builder delivery

The user develops Claude Builder first and wants a single Codex sync command to migrate new features, verify them and release an installable Codex plugin, plus the equivalent of the maintainer's Claude update-local rollout. Keep both packages in lukekeith/builder: Claude at root, Codex under codex/, separate tags at matching adapted versions. Preserve the existing Codex port's uncommitted snapshot without changing its worktree.

Sync is a semantic agent workflow, not blind runtime/prose replacement. A checked-in upstream baseline and complete per-file disposition report cover additions, changes and deletions. Five exact shared helpers can be copied only after all destination conflicts are checked. Other files must be adapted, mapped to tested equivalents or explicitly excluded for runtime reasons. Full tests and review precede baseline advancement; a content/permission digest ties verified package identity to the release. Codex-specific isolation, durable artifacts, native workers and exact landing proof remain binding. Latest source is local main by default; pinned refs keep a migration stable.

Release requires clean main, current upstream coverage and an unchanged verified package. Tests run freshly, main advancement invalidates the candidate, and packaging uses the exact Git commit. The separate builder-codex--vVERSION tag and main are atomically pushed before a GitHub release with a marketplace/package archive. Never force/reuse a colliding tag. No changes to Claude release tags or consumer config formats.

Update-local uses supported Codex CLI marketplace/installation commands, verifies the actual installed runtime rather than the session's loaded package, and reports per-project results. It mirrors d2m/fai-cd/makeready/fai-erp global install plus finpro vendor mode. A known old local marketplace can transition to the published source with registration rollback; unrelated conflicts are not silently replaced. Runtime vendoring preserves host settings/facts and unrelated entries, excludes maintainer/source metadata, rejects traversal/symlinks/unowned destinations, and protects uncommitted/local edits with ownership and digests. Whole-tree replacement retires removed files. Consumer commits are never automatic.

Acceptance: upstream 4.9.1 behavior is explicitly mapped/adapted; incomplete/stale reports and failed tests cannot certify sync; package/source drift and tag/branch/dirty/race errors block release; real Codex CLI loads 4.9.1 from the catalog; source switching and runtime-only vendoring work in an isolated host; local edits and valid TOML formatting are protected; release archive installs and published Git source is discoverable. Existing open sessions need a new session to load updates.

Scope excludes Claude status-line bindings and detached fleet persistence; native Codex workers own execution. Repository-wide Claude tidy remains excluded. No automatic changes to the five real consumer repositories are needed to implement/test the rollout command.
