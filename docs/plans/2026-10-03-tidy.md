# Nothing left behind — implementation plan

> Executed inline (superpowers:executing-plans), then one whole-branch review on the most capable model.

**Goal:** Fleets merge into a configured branch and leave nothing behind; one inventory shows every
branch and worktree; `/builder:tidy` takes a messy repo back to clean.

**Spec:** `docs/specs/2026-10-03-tidy-design.md`

## Global Constraints

- Never push, never touch remote branches, never discard uncommitted work (restore only test output;
  stash everything else by name), never delete an unmerged branch except by `force-delete-branch`.
- `merge_into` defaults to `base_branch`; old configs read unchanged.
- Release 4.8.0. Commits `<area>(<scope>): <subject>`, lower case, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests: `node --test scripts/test/<file>.test.mjs`. Known timing flakes: fleet "keeps talking", job
  "wait gives up" — re-run alone before calling them red.

## Review Focus

1. A merged feature whose worktree holds a real uncommitted code change — must be stashed by name,
   never lost (Task 2/3).
2. The target branch checked out in another worktree, or dirty in the main checkout — park with the
   reason, nothing half-merged (Task 1).
3. A branch whose name matches no manifest but has unmerged commits — `unknown`, never auto-deleted
   (Task 4/5).
4. A fleet row still `running` (lock alive) — the inventory never proposes touching its branch or
   worktree (Task 4).
5. An old `fleet.json` whose `target` differs from the new `merge_into` with unfinished rows — refuse
   with the `--into` that continues it (Task 1).

## Tasks

### Task 1: `merge_into` and `--into` decide the fleet's target
- Modify `scripts/config.mjs` (expose `mergeInto: fm.merge_into ?? baseBranch`), `scripts/fleet.mjs`
  (`--into <branch>` flag; `TARGET = opt('--into') ?? CFG.mergeInto`; drop the HERE-is-target rule
  and the detached-HEAD refusal; refuse a missing target branch; refuse a saved `fleet.target` that
  differs while rows are unfinished, naming `--into <old>`; the `--detach` re-spawn passes `--into`
  through). Dry-run line: `merges into: <target> (merge_into)` or `(--into)`.
- Tests (`fleet.test.mjs`): the fleet launched from another branch lands on `main` (config default);
  `--into release` lands on `release`; a detached HEAD launch works; a missing target refuses with
  exit 2; a saved different target with unfinished rows refuses naming `--into`. Update existing
  tests that relied on landing on the checked-out branch.

### Task 2: `tidy-core.mjs` — `TEST_OUTPUT`, `isTestOutput`, `clearWorktree`
- Create `scripts/tidy-core.mjs`:
  - `TEST_OUTPUT = ['test-results/', 'playwright-report/', 'coverage/', '.nyc_output/', '.builder/']`
    plus `/^junit[^/]*\.xml$/` on the basename; `isTestOutput(path): boolean`.
  - `clearWorktree(root, wt, label, today = new Date()) → { removed, stash, restored }` per spec §2.
- Tests (`tidy-core.test.mjs`): restores a dirty `test-results/.last-run.json` and removes the
  worktree with `stash: null`; a dirty real file is stashed with message
  `builder: <label> leftovers YYYY-MM-DD` (visible in `git stash list`) and the worktree removed; a
  missing path returns `{ removed: false }` after `worktree prune`.

### Task 3: the fleet clears on landing and at exit
- `landNow`: replace the clean-only removal with `clearWorktree(ROOT, f.worktree, feature)`; then
  `git branch -d f.branch` unless it is TARGET or `CFG.baseBranch`; a stash → `addNote(<feature>
  merged; uncommitted changes from its worktree are in stash "<msg>")`. Remove the "kept (it has
  changes)" note.
- Fleet exit (after the `waiting → parked` loop): for rows `parked`/`failed` with a worktree →
  `clearWorktree`, `f.worktree = null`, keep branch; then `addNote(inventorySummary(...))` (Task 4)
  before `save()`.
- Tests: a landed feature with `test-results/` dirty in its worktree leaves no worktree and no
  branch; a landed feature on a non-`builder/` branch (manifest `branch: feat/x`) has that branch
  deleted; a parked feature at exit has no worktree, keeps `builder/<f>`, and a second run picking it
  recreates the worktree.

### Task 4: the inventory
- `tidy-core.mjs`: `inventory(root, cfg, target, { now, lockAlive, fleet }) → items[]` and
  `summaryLine(items) → string`, per spec §3; feature-branch detection via
  `git cat-file -e <b>:<registry>/<f>/MANIFEST.md` for `builder/<f>` and
  `git grep -l -e '^branch: <b>$' <b> -- <registry>` otherwise; manifest read with `git show`.
- Create `scripts/inventory.mjs [--into b] [--json|--summary]` (table by default).
- Tests: a fixture repo with one item per group (merged, ready, parked, in-progress, unknown,
  current, running via a live lock + fleet row, dead worktree via detached HEAD and via a deleted
  path) — each lands in its group; `summaryLine` wording and `repo: clean`.

### Task 5: `tidy.mjs` — plan and apply
- Create `scripts/tidy.mjs`: `plan [--into b] [--json]` (items + `action`), `apply <action>
  <name>… [--into b]` with `delete-branch`, `force-delete-branch`, `remove-worktree`, `merge` per
  spec §4 (feature branches not carrying the target → print the fleet command instead of merging,
  exit 0 with `handed: <features>` so the skill launches it).
- Tests (`tidy.test.mjs`): `plan --json` actions on the Task 4 fixture; `apply delete-branch` on an
  unmerged branch refuses (exit 1, branch still there); `apply remove-worktree` stashes a real change;
  `apply merge` of a branch carrying the target merges `--no-ff` onto it.

### Task 6: skills and text
- Create `skills/tidy/SKILL.md` per spec §4.
- `skills/status/SKILL.md`: run `inventory.mjs --summary`, print it under the table.
- `skills/help/SKILL.md`, README: name `/builder:tidy`; `merge_into`.
- `skills/agent`, `skills/fleet`, `skills/resume` (description + body), README: "the branch you're
  on / it was run from" → "the `merge_into` branch (default `base_branch`), or `--into`".
- `PROJECT.template.md`, `skills/init/SKILL.md`: `merge_into` (optional; asked only when a
  `develop`-style branch exists).
- Tests (`skills-consistency.test.mjs`): tidy skill drives `tidy.mjs`, help names it, status runs
  `inventory.mjs --summary`, no skill says features land on the branch you are on / it was run from.
